# Password Generator

Потоковый генератор парольных кандидатов. Версия 2 использует один шаблонный
движок вместо отдельных `pure_dictionary`, `mask`, `hybrid` и `combinator`.

## Установка

Для запуска команды из любого терминала рекомендуется `pipx`: он создаёт
отдельное окружение для утилиты и не изменяет системный Python.

### Установка для разработки

В каталоге проекта выполните:

```powershell
pipx install --editable .
passgen --version
```

Флаг `--editable` удобен во время разработки: изменения исходников и текстов
справки сразу видны в команде `passgen`. Если после установки терминал не
находит команду, выполните `pipx ensurepath`, полностью закройте и заново
откройте терминал.

### Перенос на другой компьютер

1. Установите Python 3.10 или новее и `pipx`. В Kali/Debian это обычно
   `sudo apt install pipx`; в Windows PowerShell можно выполнить
   `py -m pip install --user pipx`, затем `py -m pipx ensurepath` и
   перезапустить терминал.
2. Скопируйте каталог проекта вместе с `pyproject.toml`.
3. Откройте терминал в скопированном каталоге и выполните:

   ```powershell
   pipx install .
   passgen --version
   ```

После этого `passgen` доступна из любого каталога. Для обновления установки
после переноса новой версии выполните в её каталоге `pipx install --force .`.
Удаление утилиты: `pipx uninstall password-generator`.

## Быстрый CLI

Одна маска:

```powershell
passgen -p 'Password?d?d!' --plan
passgen -p 'Password?d?d!' -o outputs/password_digits.txt
```

Словарь, маска и комбинация словарей за один запуск:

```powershell
passgen `
  -p '{names}' `
  -p '{names}?d?d' `
  -p '{names}_{years}' `
  --wordlist names dictionaries/names.txt `
  --wordlist years dictionaries/years.txt `
  --wl-min-length names 3 `
  --wl-max-lines names all `
  --plan
```

Custom charset в стиле hashcat:

```powershell
passgen `
  -p '?1?1{names}' `
  --charset1 'йцук' `
  --wordlist names dictionaries/names.txt `
  --plan
```

Подкоманды `generate` нет: быстрый запуск всегда начинается сразу с
`passgen -p ...`.

CLI-запуск можно сразу сохранить как YAML. Команда продолжает обычный запуск;
добавьте `--plan`, если нужно только создать конфиг без генерации:

```powershell
passgen -p '{names}?d?d' `
  --wordlist names dictionaries/names.txt `
  --save-config configs/names.yaml `
  --plan
```

По умолчанию существующий output атомарно объединяется с новыми кандидатами.
`--force` вместо объединения атомарно заменяет output, а существующий файл
конфигурации заменяется отдельным `--overwrite-config`. Сохранять конфиг поверх
словаря, rule-файла или output запрещено независимо от этих флагов.

## YAML-конфигурация

Готовый копируемый шаблон с построчными пояснениями и десятью вариантами
использования: [config_template.yaml](config_template.yaml). Его активная часть
небольшая и запускаемая, а альтернативы оставлены комментариями, чтобы их можно
было включать по одной.

Минимальный рабочий конфиг действительно короткий:

```yaml
version: 2
patterns:
  - "Password?d?d!"
```

Без дополнительных секций используются безопасные значения по умолчанию:
`candidates.txt`, UTF-8, атомарное объединение с существующим output, точная
дедупликация на диске и фильтрация управляющих символов. Перед генерацией
интерактивный запуск запрашивает подтверждение.

```powershell
passgen from-config config_template.yaml --plan
passgen from-config config_template.yaml
```

Проверка без записи output:

```powershell
passgen from-config config_template.yaml --check
```

### Быстрый путь: свой YAML за минуту

1. Скопируйте [config_template.yaml](config_template.yaml) под новым именем,
   например `my_passgen.yaml`.
2. Измените минимум `patterns` и `output.path`; при использовании словаря
   добавьте его в `wordlists`.
3. Выполните `passgen from-config my_passgen.yaml --check`.
4. Посмотрите объём работы через `--plan`, затем запустите генерацию.

Внутри `config_template.yaml` есть пояснения к активным строкам и рецепты для
масок, словарей, гибридов, двух словарей, charsets, мутаций, фильтров и output.
Комментарии, начинающиеся с `#`, YAML игнорирует, поэтому шаблон можно
запускать без изменений. [config_generator.yaml](config_generator.yaml) остаётся
расширенным исполняемым демонстрационным сценарием, где несколько возможностей
работают одновременно.

Если перенести YAML, например в `configs/my_passgen.yaml`, пути внутри него
тоже нужно пересчитать: `dictionaries/names.txt` станет
`../dictionaries/names.txt`.

### Все команды для работы с конфигурацией

#### Запуск существующего YAML

Полный синтаксис:

```text
passgen from-config CONFIG [--check | --plan] [--yes] [--force] [-o PATH | --output PATH] [--stats]
```

| Команда | Что делает |
|---|---|
| `passgen from-config CONFIG` | Показывает план, при интерактивном запуске запрашивает подтверждение и генерирует кандидаты. |
| `passgen from-config CONFIG --check` | Проверяет YAML, паттерны, используемые словари и существующий output; файлы результата не создаёт. |
| `passgen from-config CONFIG --plan` | Только показывает план и оценку количества кандидатов, без генерации. |
| `passgen from-config CONFIG --yes` | Запускает без интерактивного подтверждения. |
| `passgen from-config CONFIG --force` | Временно включает замену output вместо объединения с его старым содержимым. |
| `passgen from-config CONFIG -o PATH` | Временно заменяет `output.path` из YAML. Полная форма: `passgen from-config CONFIG --output PATH`. |
| `passgen from-config CONFIG --stats` | После генерации выводит статистику: фильтрации, дубликаты и число записанных кандидатов. |
| `passgen from-config -h` | Показывает краткую справку. Полная форма: `passgen from-config --help`. |

`--check` и `--plan` нельзя указывать вместе. Флаги `--yes`, `--force`,
`--output` и `--stats` можно комбинировать с обычным запуском. Пути внутри YAML
разрешаются относительно самого YAML-файла, а относительный путь в `-o` / `--output`
— относительно текущего каталога терминала.

После `--force` объединение снова включается только через
`output.overwrite: false` в YAML: отдельного флага `--no-force` нет.
Для запуска `CONFIG` должен иметь расширение `.yaml` или `.yml`. Значение
`-o -` направляет кандидаты в stdout, сохраняя заданную в YAML кодировку output.

Обычная последовательность работы:

```powershell
passgen from-config my_passgen.yaml --check
passgen from-config my_passgen.yaml --plan
passgen from-config my_passgen.yaml --yes --stats
```

#### Сохранение CLI-запуска в YAML

| Команда | Что делает |
|---|---|
| `passgen -p PATTERN ... --save-config FILE.yaml` | Сохраняет эквивалентную YAML-конфигурацию и затем обычно продолжает генерацию. |
| `passgen -p PATTERN ... --save-config FILE.yaml --plan` | Сохраняет конфиг, показывает план и не генерирует кандидаты. Это удобный способ создать первый YAML. |
| `passgen -p PATTERN ... --save-config FILE.yaml --overwrite-config --plan` | Разрешает заменить уже существующий YAML-файл. Без `--save-config` этот флаг недопустим. |

`--save-config` принимает только имена с расширением `.yaml` или `.yml`. Не
путайте `--overwrite-config` с `--force`: первый заменяет конфиг, второй заменяет
файл кандидатов.

Сохраняемый YAML покрывает большинство флагов CLI:

| Флаги CLI | Поле YAML |
|---|---|
| `-p`, `--pattern` | `patterns` |
| `--wordlist`, `--wl-min-length`, `--wl-max-length`, `--wl-max-lines`, `--wl-encoding`, `--wl-require`, `--wl-forbid` | `wordlists` |
| `--zip-wordlists NAME1,NAME2` | `generation.zip_wordlists` |
| `--charset`, `--charset1` … `--charset4` | `charsets` |
| `--mutation`, `--mutation-mode`, `--include-original`, `--no-include-original`, `--rule-file` | `mutations` |
| `--result-min-length`, `--result-max-length` | `result_filters` |
| `--confirm-above` | `generation.confirm_above` |
| `--max-passwords` | `generation.max_passwords` |
| `-o`, `--output`, `--encoding`, `--force` | `output` |

После автосохранения вручную можно добавить возможности, которых нет у быстрого
CLI: `apply_mutations` для отдельного паттерна, `result_filters.require/forbid`,
а также `encoding` и `max_rules` для rule-файла.

`--check` компилирует паттерны, сканирует используемые словари и заранее
отклоняет конфигурацию, если хотя бы один базовый кандидат может превысить
жёсткий предел длины. Уже существующий output также должен быть обычным файлом;
несуществующие output и родительские каталоги при проверке не создаются.

Поддерживается только строгая схема `version: 2`. Пути внутри YAML разрешаются
относительно самого конфигурационного файла. Основной репозиторный шаблон —
`config_template.yaml`; после установки пакета без исходного репозитория
создайте собственный YAML по минимальному примеру выше.

## Синтаксис паттернов

| Токен | Значение |
|---|---|
| `?l` | латинские строчные буквы |
| `?u` | латинские заглавные буквы |
| `?d` | цифры |
| `?s` | пробел и ASCII punctuation |
| `?a` | все 95 печатных ASCII-символов |
| `?h`, `?H` | hex в нижнем/верхнем регистре |
| `?1` … `?4` | пользовательские charsets |
| `?{name}` | именованный charset |
| `{name}` | значение именованного словаря |
| `??`, `{{`, `}}` | литеральные `?`, `{`, `}` |

Встроены `?{cyrillic_lower}` и `?{cyrillic_upper}`. Паттерн
`word?dkey` означает литерал `word`, одну цифру и литерал `key`.

Разные словари полностью раскрываются:

```text
{names}_{years}
```

Если нужны только пары строк с одинаковыми номерами, добавьте
`--zip-wordlists names,years`. Тогда из `admin/user` и `2025/2026` получатся
`admin_2025` и `user_2026`, а не четыре сочетания. Пара объединяется после
сопоставления физических строк: если фильтр исключил строку одной стороны,
вся пара пропускается. Если число физических строк различается, `--plan`
выдаст ошибку до записи файла. Для нескольких независимых пар флаг можно
повторить.

Повтор одного имени использует то же выбранное слово:

```text
{names}_{names} -> admin_admin, user_user
```

## Мутации

В CLI указанные мутации применяются ко всем паттернам:

```powershell
passgen `
  -p '{names}' `
  --wordlist names dictionaries/names.txt `
  --mutation capitalize_first,uppercase `
  --mutation 'replace=a,@'
```

Мутации можно перечислять через запятую, в том числе смешивать простые и
параметризованные: `--mutation 'uppercase,replace=a,@,append=2026'`.
Флаг также можно повторять. В PowerShell список с пробелами заключайте в
кавычки. Запятую внутри значения экранируйте обратной косой чертой,
например `--mutation 'append=foo\,bar,reverse'`.

Лимит числа уникальных паролей в итоговом файле задаётся через
`--max-passwords N`, например `passgen -p '?l?l?l?d' --max-passwords 100 -o passwords.txt`.
При обычном объединении учитываются и уже сохранённые строки. Если в файле
больше N уникальных паролей, запуск завершается без изменения файла; `--force`
позволяет заменить его новым результатом.

В YAML мутации можно включить только для выбранного паттерна через
`apply_mutations: true`. Поддерживаются режимы `independent` и `chained`, а
также строго проверяемое подмножество `.rule`-файлов hashcat — не весь язык
правил hashcat.

Поддерживаемые операции rule-файлов:

```text
: l u c C t Tn r d pN f { } $x ^x [ ] Dn xNM ONM 'N
iNx oNx sxy @x k K *NM q zN ZN yN YN E
```

Пробелы-аргументы сохраняются. Пустые строки и строки, начинающиеся с `#`,
игнорируются. Защитные пределы: 4 096 символов на одно правило, 100 000
операций мутаций суммарно и 1 000 000 символов на один кандидат. Это не
заменяет `result_filters.max_length`, который стоит задавать по требованиям
конкретной проверки.

## Планирование и output

План теперь показывается перед каждой генерацией по умолчанию. Флаг `--plan`
останавливает выполнение после показа плана и не запускает генерацию. Для
`uppercase`, `lowercase`, `capitalize_first`, `ru_to_eng`,
`url_encode_specials`, `append` и `prepend` в режиме `independent` учитываются
мутации, которые ничего не изменяют. Для сложных и chained-правил выводится
консервативная верхняя граница. Итоговая строка плана показывает количество до
применения глобальных фильтров и дедупликации.

После плана интерактивный запуск запрашивает подтверждение до начала генерации.
`--yes` пропускает вопрос. Неинтерактивный запуск выполняется автоматически,
пока оценка не превышает `confirm_above`; при превышении требуется `--yes`.

Кандидаты пишутся потоково во временный `.part`-файл, а точная дедупликация
всегда выполняется во временной SQLite-базе. Готовый output появляется атомарно
только после успешного завершения. При обычном прерывании `Ctrl+C` уже
записанные целые строки сохраняются отдельно: для `passwords.txt` это
`passwords.partial.txt` (или `passwords.partial-2.txt`, если первый файл уже
есть). Основной output при этом не меняется. Такой файл — частичный результат,
а не точка возобновления генерации.

Если output уже существует, без `--force` формируется упорядоченное объединение:
сначала первые вхождения старых строк, затем новые уникальные кандидаты. Поэтому
повторный запуск не добавляет уже имеющиеся строки, а старые дубли также
удаляются. Последняя строка без перевода строки и CRLF читаются корректно;
результат нормализуется к `LF`. Старый файл читается строго в `output.encoding`.
Ошибка декодирования, генерации или временной базы оставляет его неизменным.

С `--force` старое содержимое не читается и output целиком заменяется уникальными
кандидатами текущего запуска. В YAML этому соответствует
`output.overwrite: true`.

На время записи используется соседний advisory lock
`.OUTPUT.passgen.lock`, поэтому два процесса passgen не могут одновременно
изменять один output. Lock-файл остаётся как стабильная точка синхронизации.
Изменение output внешней программой обычно обнаруживается сравнением состояния
файла перед `os.replace`; это дополнительная защита, но внешние программы не
обязаны соблюдать lock, и между проверкой и заменой остаётся небольшое окно
гонки. После жёсткого завершения могут остаться служебные `.part` или
`.sqlite3`; они не считаются готовым результатом. Checkpoint/resume пока не
реализован.

Выбор режима дедупликации удалён из CLI и YAML: точная disk-дедупликация
обязательна, включая вывод в stdout.

## Справка `-h`

Редактируемые русские тексты справки находятся в:

```text
password_generator/help/ru.yaml
```

Вызов `passgen -h` показывает единую справку: быстрый CLI, YAML-конфигурацию
и дополнительные флаги. Вызов `passgen from-config -h` намеренно выводит ту же
общую справку, а не отдельный раздел. При повреждённом help-файле CLI использует
минимальный встроенный fallback.

```powershell
passgen -h
```
