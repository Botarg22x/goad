AUTHCHECKER RUN — ПОДРОБНАЯ ПРОВЕРКА ВХОДА

Использование: authchecker run (--report FILE | -u URL|FILE) (--live | --dry-run) -l LOGIN|FILE -p PASSWORD|FILE [ПАРАМЕТРЫ]

# ==================== ОСНОВНОЕ ====================

authchecker run --dry-run --report report.json -l admin -p passwords.txt
authchecker run --live -u https://example.ru/login -l admin -p passwords.txt --slow
authchecker run --live -u https://example.ru/private -l admin -p passwords.txt --slow

--dry-run не обращается к цели и требует готовый отчёт. -u с --live сначала
анализирует указанную страницу; сайт целиком не обходит.
Для HTTP Basic передайте точный защищённый URL: шаблон продукта не нужен.

# ==================== ВХОДНЫЕ ДАННЫЕ ====================

-r, --report FILE         Готовый JSON-отчёт PointFinder
-u, --pages URL|FILE     Готовая страница входа или TXT-файл URL
-t, --template PRODUCT   Шаблон продукта для -u
-l VALUE|FILE            Один логин или существующий файл; можно повторять значения
-p VALUE|FILE            Один пароль или существующий файл; можно повторять значения
--logins FILE            Явно указать файл логинов
--passwords FILE         Явно указать файл паролей
--live                   Выполнить проверки входа
--dry-run                Показать план без сетевых запросов

# ==================== СКОРОСТЬ И СЕТЬ ====================

--slow                   Одна попытка в 15 с и один поток
--rate N                 Попыток в секунду; по умолчанию 1, максимум 10
--threads N              Потоки; по умолчанию 1, максимум 10
--max-per-account N      Предел на точку и логин; без флага явного предела нет
--max-total N            Общий предел попыток
--timeout N              Таймаут запроса; обычно 10 с
--proxy URL              HTTP-прокси
--ca-cert FILE           CA для проверки HTTPS через прокси
--scope-domain DOMAIN    Разрешённый домен для отчёта с несколькими хостами
--allow-subdomains       Разрешить его поддомены

# ==================== РЕЗУЛЬТАТ ====================

--compact                Короткий итог по каждой точке вместо JSON
--audit FILE             Путь к журналу попыток без паролей
--save-report FILE       Сохранить анализ страницы из -u
--auto-browser           С отчётом: HTTP, затем браузер при необходимости
--headless               Не показывать окно явного браузерного режима
-h, --help              Показать эту справку

Подтверждённая успешная пара выводится сразу; одного HTTP 200 или 302
для вывода об успехе недостаточно.
Если результат не определён, пара и коды ответа выводятся сразу для ручной
проверки; это не означает успешный вход.
